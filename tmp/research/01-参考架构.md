# 01 通用 Agent 参考架构

> 调研目标：为 job-helper（对话驱动、本地优先、单用户的求职 Agent）提炼可借鉴的通用 Agent 架构蓝图。调研对象为 6 个最具代表性的开源/官方框架。

## 调研对象（框架清单 + 链接 + 一句话定位）

| 框架 | 链接 | 一句话定位 |
|---|---|---|
| OpenAI Agents SDK | https://openai.github.io/openai-agents-python/ | 官方最小原语集（Agent/Handoff/Guardrails/Sessions/Tools），内置 agent loop 与 HITL |
| Anthropic Claude Code / Agent SDK | https://code.claude.com/docs/en/ | Agentic Coding 标杆：模型推理 + 工具行动的 "agentic harness"，权限/记忆/Skill/子代理体系最完整 |
| LangGraph | https://langchain-ai.github.io/langgraph/ | 把 agent 运行时建模为显式状态机（StateGraph），checkpointer 实现持久化可恢复 |
| Microsoft AutoGen | https://microsoft.github.io/autogen/ | 事件驱动 Actor 模型的多 Agent 框架（Core 底层 + AgentChat 高层 GroupChat） |
| CrewAI | https://docs.crewai.com/concepts/crews | 角色化（role/goal/backstory）多 Agent，顺序 vs 层级（manager 委派）两种流程 |
| LlamaIndex Agents | https://developers.llamaindex.ai/python/framework/understanding/agent/ | 工具即函数/即 QueryEngine，RAG 管线作为一等工具接入 agent 循环 |

## 共性架构分层

**1. 控制循环 / 编排**（所有框架的核心）
- 都是"模型决定下一步 → 调工具 → 结果反馈回循环 → 判断完成"的 agent loop。
- 实现差异：AI SDK / OpenAI / Claude 内置 loop；LangGraph 用节点+条件边显式定义循环；AutoGen 用事件驱动消息循环；Claude Code 描述为 gather context → take action → verify results 三阶段自适应循环。

**2. 状态管理**（三档，全部框架必备但侧重不同）
- 短状态：本次循环内的消息与临时上下文。
- 中状态：单次 run/thread 可恢复。LangGraph 用 checkpointer + thread_id 快照（durable execution）；Claude Code 用 JSONL 会话文件（可 resume/fork）；OpenAI 用 Sessions（有 SQLite/Redis/MongoDB 适配器）。
- 长状态：跨会话记忆（见记忆层）。
- 上下文管理：Claude Code 最完整——自动压缩（先清旧工具输出再摘要对话）、Skills/MCP 工具定义按需延迟加载、subagent 独立 context 隔离膨胀。

**3. 工具层**
- 统一模式：任意函数即工具（OpenAI/LlamaIndex/crewAI），schema 自动生成（Pydantic/zod）+ 校验。
- 标准化协议：MCP 成为跨框架通用工具接入标准（OpenAI、Claude、LangGraph 均支持）。
- 分层能力：Claude Code 把工具分五类（文件/搜索/执行/Web/代码智能），权限按类分级。
- 工具结果必须回流循环驱动下一步决策（agentic 的本质）。

**4. 记忆层**
- 三层结构：①对话/工作记忆（短）；②持久指令与领域知识（Claude Code 的 CLAUDE.md、skill 描述）；③自动沉淀记忆（Claude Code auto memory：MEMORY.md 前 200 行自动加载进上下文；crewAI 的 short/long/entity memory；LangGraph 的 Store 跨线程长期记忆）。
- 关键设计：记忆按"描述在上下文、正文按需加载"控制 token 成本（Claude Code skills 机制）。

**5. 规划**
- 隐式规划：agent loop 内模型自组织多步（Claude Code 三阶段）。
- 显式规划：LangGraph 图即计划；Claude Code Plan mode（先探索出方案、用户批准再执行）；CrewAI hierarchical（manager agent 拆解委派并校验）。
- 任务清单：Claude Code 用 todo list 跟踪多步任务。

**6. 审批与护栏**
- 权限分级（Claude Code 四档：Manual / Accept edits / Plan / Auto，settings.json 白名单免问）。
- Guardrails（OpenAI）：输入输出校验与执行并行、fail-fast。
- Human-in-the-loop：OpenAI 内建 HITL；LangGraph interrupt 挂起/恢复；AutoGen UserAgent 人工审批。
- Checkpoints（Claude Code）：写文件前快照，可回退（类 git 的安全网）。
- 终止条件：AutoGen Termination Condition；AI SDK stopWhen 步数上限。

**7. 多 Agent**
- 四种模式：handoff 委派（OpenAI）、subagent 派生隔离 context（Claude，推荐长会话）、supervisor 主管调度（LangGraph/CrewAI hierarchical）、group chat 会话语（AutoGen）。
- Claude Code 团队实践：lead agent 协调 + 子代理并行 + 摘要回传，避免上下文爆炸。

## 各框架差异点

| 框架 | 编排模型 | 状态持久化 | 工具协议 | 记忆 |
|---|---|---|---|---|
| OpenAI Agents SDK | 内置 loop + handoff | Sessions（SQLite/Redis 等适配器） | 函数工具 + MCP | Sessions 工作记忆 + Guardrails |
| Claude Code / Agent SDK | harness loop + subagents | 会话 JSONL + 文件 checkpoint | 内置工具 + MCP + Skills | CLAUDE.md + auto memory + Skills |
| LangGraph | 显式状态图（StateGraph） | checkpointer（thread_id）+ Store | LangChain 工具 + MCP | Store 长期记忆 |
| AutoGen | 事件驱动 Actor + GroupChat | 消息流（状态由应用管理） | 函数工具 | 各 Agent 内存 |
| CrewAI | 角色化顺序/层级 | checkpointing（恢复用） | 函数工具 + 结果缓存 | short/long/entity memory |
| LlamaIndex | ReAct/Function loop + AgentWorkflow | State 对象 | 函数 + QueryEngine（RAG 即工具） | context memory |

## 对 job-helper 的架构启示（分阶段，含优先级）

**现状盘点**：单 Agent（ToolLoopAgent + 单一 SYSTEM_PROMPT）+ 工具工厂 + 两段式审批（领域自研 HITL）+ 确定性护栏（channel-guard / apply-state 纯函数）+ SQLite 消息表 + MAX_HISTORY_ROUNDS=20 硬截断。缺：记忆层、规划层、上下文管理、多 Agent、可观测性。

**P0（先做，强化现有单 Agent 骨架）**
1. **结构化会话状态**：把简历/岗位 ID、状态机位置等关键实体从对话历史抽离为 session_state（SQLite 表），每次注入 system prompt——解决 20 轮截断丢上下文（对应 LangGraph 状态 / Claude Code 上下文管理）。
2. **持久记忆层（第一步）**：SQLite 存"用户偏好 + 领域事实"键值记忆，会话开头加载前 N 条（借鉴 Claude auto memory / CrewAI entity memory），后续再演进向量检索。
3. **护栏框架化**：把现有确定性纯函数护栏升级为工具级输入/输出 guardrails（AI SDK schema 已有输入侧，补输出校验回调），校验独立于业务执行（OpenAI Guardrails 思路）。
4. **审批分级**：按权限分档——只读类工具（list/analyze）免确认、写入类（applyJob/recordStatus）确认；支持用户侧"此工具以后免问"白名单（Claude Code permission modes 思想）。补充任务完成判定替代纯步数 stopWhen。

**P1（后做，中期）**
5. **规划层**：复杂任务（如"帮我准备面试"）先 plan-then-execute——模型产出步骤清单 → 用户确认 → 逐步执行（Claude Code Plan mode / LangGraph 条件边思想）。
6. **Skill 系统**：把 resume-analysis / job-match / interview-prep 等提示词从大 SYSTEM_PROMPT 拆为按需加载的 skill 包（描述进上下文、正文用时加载），控制 token（Claude Skills 机制）。
7. **多 Agent（轻量）**：单用户场景推荐 supervisor + subagent 模式（Claude 动态工作流）而非 group chat；子代理独立 context 隔离，长会话收益明显。
8. **可观测性**：记录每轮工具调用、耗时、token，写 SQLite/logs（严守敏感信息过滤硬约束；OpenAI Tracing / Claude hooks 思路）。

**P2（远期/可选）**
9. **RAG 化**：简历库/历史岗位向量化，作为工具注入 agent（LlamaIndex QueryEngine 即工具思想）。
10. **图编排**：若流程复杂度需要显式状态机（目前业务状态机已在 apply-state 层，暂不需 LangGraph 级图运行时）。
11. **事件驱动/异步**：AutoGen Actor 模型对单用户本地场景收益低，除非未来做异步任务（如定时轮询岗位）。
