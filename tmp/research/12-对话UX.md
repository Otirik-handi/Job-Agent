# 12 对话驱动 Agent 的交互与 UX 设计

日期：2026-08-10
状态：调研完成，供 job-helper 会话体验与多步任务可见性优化对照参考
目的：回答「Agent 执行过程怎么展示 / 确认点怎么做 / 渐进式披露如何落地 / 结构化数据如何在对话中呈现 / 长任务怎么中断恢复」五个核心问题，并给出 job-helper 的 P0/P1/P2 建议。

## 调研对象（链接 + 一句话）

1. **Claude Code Best Practices**（https://code.claude.com/docs/en/best-practices）—— Anthropic 官方：如何让 agent 边执行边汇报、用测试/证据收尾、分级权限确认、Esc 中断与 checkpoint 回退。
2. **Claude Code Checkpointing**（https://code.claude.com/docs/en/checkpointing）—— 每个用户输入自动存 checkpoint，可回退/恢复/压缩上下文的会话状态管理权威文档。
3. **Claude Code Configure permissions**（https://code.claude.com/docs/en/permissions）—— 权限模式谱系 default→acceptEdits→plan→auto→bypassPermissions，即确认强度分级。
4. **Anthropic Building Effective Agents**（https://www.anthropic.com/engineering/building-effective-agents）—— 官方 agent 工程范式：agent 在执行中"在 checkpoint 处暂停等人工反馈"、必须设停止条件、ACI（agent 接口）要像 HCI 一样投入设计。
5. **OpenAI Deep Research 发布文**（https://openai.com/index/introducing-deep-research/，经 Wayback 存档抓取）—— 长任务展示范式：侧栏步骤+来源摘要、5-30 分钟耗时预估、离开后通知、可中途打断追加指令、最终报告进对话。
6. **NN/g Progressive Disclosure**（https://www.nngroup.com/articles/progressive-disclosure/）—— 渐进式披露经典准则：主次层级切分、不超过 2 级、进阶按钮要有信息气味；staged disclosure（向导）为变体。
7. **NN/g Chatbots 可用性研究**（https://www.nngroup.com/articles/chatbots/）—— 对话中用户偏好按钮/预填选项而非手打长文本；强制纯选项会限制探索路径。
8. **Adaptive Cards**（https://learn.microsoft.com/en-us/adaptive-cards/）—— 对话/宿主应用内结构化卡片交换格式：声明式 JSON、FactSet 键值对、输入控件、宿主渲染原生 UI，内容与布局分离。

## Agent 过程可见性（tool call 展示/步骤列表最佳实践）

- **两种主流模式**：① 流式 tool call 卡片流（Claude Code、Vercel AI SDK 的 tool 分区、本机 ZCode：每次调用一行卡片=工具名+参数摘要，点击展开详情，完成后折叠）；② 摘要式步骤列表（ChatGPT Deep Research：侧栏显示"步骤摘要 + 引用来源"，主对话只出最终报告）。
- **结论：两者结合最佳**。实时执行阶段用流式卡片（标题行=工具名+一句话状态，可展开详情），保持对话不被打断；长任务另配侧栏/面板步骤清单跟踪整体进度，任务结束后步骤折叠成一行"已执行 N 步"留在对话流。
- **展示节奏**：running（脉冲/微动效）→ completed（绿勾）→ failed（红，附错误摘要+重试入口）。Claude Code 明确要求 "show evidence rather than asserting success"（贴出命令输出/测试结果/截图作证据，而不是口头说成功）。
- **别刷屏**：不要每条 tool call 都写一行自然语言进对话（话痨）；工具执行信息用卡片承载，主对话只保留总结与结论。
- Deep Research 侧栏可实时跟踪、可 interrupt 并追加修正指令——即"执行可被观察 + 可被干预"双要求。

## 确认点交互模式

- **分级谱系（Claude Code 权限模式，权威）**：default（每次询问，安全但累）→ acceptEdits（自动接受低风险文件编辑）→ plan（只读规划模式）→ auto（独立分类器后台审核，只拦可疑动作）→ bypassPermissions（跳过确认，仅剩 rm -rf / 等熔断）。官方原话："第十次确认后你已不是在 review，只是机械点击"——确认必须分级，避免确认疲劳。
- **确认强度与动作成本匹配**：无副作用/可逆动作→轻量确认或不确认+事后可撤销；不可逆或对外有副作用（发邮件、投递、改简历）→强确认。Anthropic 范式：agent 在 checkpoint 或遇到阻塞时"暂停等人"，同时必须有 stopping conditions（最大迭代次数等）兜底失控。
- **可中断可回退**：Esc 中断保留上下文可重定向；checkpoint/rewind 允许回退；"Undo that" 让 agent 自行撤销。
- job-helper 现状评估：`agent-tooling-conventions.md` 已实现两段式对话审批（第一段只生成摘要不落库，第二段 confirmed:true 落库）+ `confirm-dialog` 强确认，方向正确；缺的是"轻量确认/可撤销"这一档与失败重试。

## 渐进式披露的 UI 落地

- **NN/g 准则**：初始层放高频核心，次级层放高级/细节；超 2 层会迷路（3 层以上低可用性）；进阶入口按钮要有明确"信息气味"（标签说清点了会看到什么）。
- **落地的具体模式**：① 摘要优先——先给 1-2 行结论再按需展开；② 折叠/accordion——tool call 详情、来源列表默认收起；③ 按需加载——"展开 N 个来源 / 查看完整报告"按钮；④ 抽屉/详情面板——列表项点击进抽屉（job-helper 已有 job-drawer/resume-drawer/tailored-resume-drawer，正符合）；⑤ staged disclosure/向导——多步骤任务分步引导（如投递流程：确认岗位→确认简历→确认投递）。
- **注意**：超过 2 级时用卡片分组替代更深层级，而非继续加层。

## 结构化数据在对话中的呈现

- **模式选择**：对话中放"汇总型卡片"（岗位 Top 列表、投递状态摘要、一句话结论）；完整表格/整份简历/长清单不放对话，进抽屉或侧栏。Adaptive Cards 证明"声明式卡片嵌入对话"可行且可带输入控件；键值对用 FactSet（标签-值）比 Markdown 表格可读。
- **交互辅助**：NN/g 研究显示用户偏好预填按钮/菜单胜过手打长文本（"should be something obvious to prepopulate it"）——常用输入（筛选岗位、确认投递）给按钮，而非让用户复述。
- **job-helper 评估**：资源侧栏（`resource-tabs`：简历/岗位/专属简历 + 状态筛选）+"抽屉详情"是正确架构——对话保持自然语言、结构化数据驻留侧栏。缺口：对话内缺少"汇总卡片"把侧栏资源与对话结论桥接（如匹配后对话里应出现一张 3-5 行岗位卡 + "可到右侧查看全部"），以及对话中状态变化（投递成功）未在对话里可视化。
- **避免话痨**：状态用 status-badge 渲染，变化用一行式事件卡（"岗位 X 状态已更新为 已投递"），不要复述整条记录。

## 长任务中断恢复与进度

- **Deep Research 范式**：长任务（5-30 分钟）给耗时预估、可离开做别的事、完成时通知、侧栏实时进度、可中断后追加修正指令/新来源。
- **Claude Code 范式（checkpointing 文档）**：每个 user prompt 自动存 checkpoint（会话+文件快照，最近 100 个，随会话保留 30 天）；Esc 中断保留上下文；`/rewind` 可只回退对话/只回退代码/回退两者；Summarize 压缩上下文（省上下文窗口）；会话可 `/resume` 恢复。
- **超时处理**：LLM/工具超时给明确错误 + 允许重试；失败卡片不消失。
- job-helper 现状：已有 stop 按钮与 streaming 禁用输入、`conversation-list` 会话恢复；缺进度指示（无"进行到第几步/共几步"）、中断后上下文提示、失败重试与"上次任务中断"标记。

## 对 job-helper 的 UX 建议（P0/P1/P2）

**P0（会话可见性 + 确认体验，小改高收益）**
1. tool-progress-card 升级为三态步骤卡片并持久化：当前只显示 running 单行且完成后即消失（`chat-panel.tsx` 里瞬时 state）；改为用 AI SDK 的 tool call 分区把"工具名+状态(运行/完成/失败)+一句话摘要"落进消息流，默认折叠可展开详情，失败卡附重试按钮。
2. 确认点分级：保留两段式强确认（applyJob/tailoredResume），把可逆操作（recordApplicationStatus、删除草稿）降为轻量确认或带撤销入口，不做二次弹窗；避免确认疲劳。
3. 失败可恢复：LLM/工具调用失败在卡片上给错误摘要 + 重试/改用其他途径的建议，而非静默失败。

**P1（多步任务可见性 + 结构化呈现）**
4. 长任务加摘要式步骤清单：批量匹配/多渠道发现执行时在对话区顶部显示"已搜索 2/5 个渠道"式进度条（Deep Research 侧栏思路的轻量版）。
5. 对话中加汇总卡片：匹配结果/投递状态用 3-5 行内联卡片呈现（岗位名+公司+匹配度+状态徽章），点击进现有抽屉；避免长 Markdown 表格。
6. 中断/恢复强化：停止后保留"任务中止于第 N 步"提示，允许用户直接追加修正指令；conversation-list 里标记未完成任务。
7. 长会话上下文压缩：超过约 20 轮后提供"总结本轮上下文"（对应 Claude Code Summarize），缓解滑动窗口截断（与综述 10 的长时记忆缺位呼应）。

**P2（兜底与工程化）**
8. 会话级 checkpoint/回退：关键动作落库前后打快照，支持回退与操作日志（对应 Claude Code rewind）。
9. 完成通知：长任务完成后浏览器通知/会话角标（Deep Research 模式）。
10. ACI 打磨：按 Anthropic 建议优化工具描述（含示例、边界、防错），降低模型误用。
