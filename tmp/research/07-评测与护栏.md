# 07 Agent 评测、安全护栏与人工确认点

> 调研目标：为 job-helper（对求职者个人数据负责、关键动作需人工确认的个人求职 Agent）提供「评测维度、权限/审批模式、人工确认点、提示注入防护」的设计参考。
> 现状对照：`src/agent/` 已实现两段式对话化审批（tailoredResume/applyJob/recordApplicationStatus）、确定性护栏（channel-guard）、纯函数+单测（见 `.agents/specs/03-agent/agent-tooling-conventions.md`）。本调研用于验证/补强该设计。

## 调研对象（链接 + 一句话）

- GAIA（arXiv:2311.12983）：通用 AI 助手基准，真实世界问答。
- AgentBench（arXiv:2308.03688）：8 个交互环境的 LLM-as-Agent 评测。
- τ-bench（arXiv:2406.12045，sierra-research/tau-bench）：用户模拟器 + 领域工具 API + 政策规则的 agent 评测，强调工具正确使用与规则遵守。
- SWE-bench（arXiv:2310.06770）：真实 GitHub issue + 隐藏测试验证 patch 的编码 agent 评测。
- BrowseComp（arXiv:2504.12516）：1266 道「难找信息」浏览题，短答案易校验。
- WebArena（arXiv:2307.13854）：四个可交互网站域（电商/论坛/协作开发/CMS）的浏览器 agent 评测。
- 权限系统：Claude Code 权限模式文档（code.claude.com/docs/en/permissions、/permission-modes）、Codex CLI 审批与沙箱文档（learn.chatgpt.com/docs/agent-approvals-security）、本机 ZCode local_setting 表。
- 提示注入与数据外发：Simon Willison 对 Claude web_fetch 数据外泄绕过案例（2026-07-15）、Codex 网络策略与 web_search cached 模式、Anthropic 多 agent 研究系统博客（2025-06-13）。

## 评测维度与基准

- **GAIA**：人类得分 92% vs GPT-4+plugins 15%——评测要测「普通任务的鲁棒性」而非把基准做难。设计启发：job-helper 的评测集应是真实求职流程问题（改简历→匹配→投递→跟进），不是抽象推理题。
- **τ-bench**：核心贡献是把「评答案」换成「对比对话结束时的数据库终态与标注目标态」，并加 pass^k（多次运行全部成功的比例）衡量一致性。事实：gpt-4o 在 airline 上 pass¹<50%、pass⁸<25%。设计启发：① 工具调用是否正确=终态是否正确，适合 job-helper 用「投递状态机终态」校验；② 单次成功高估可靠性，必须看一致性。
- **AgentBench**：指出模型 agent 主要失败在「长期推理、决策、指令遵循」。设计启发：多轮长对话（十几步的求职流程）需要专门的指令遵循评测，而非单轮问答。
- **SWE-bench**：真实仓库级问题、多文件改动、隐藏测试验证。设计启发：job-helper 的「改简历」类动作应有可验证的终态（diff + 规则校验），不能只靠模型自述。
- **BrowseComp / WebArena**：测「在真实网站上持久搜索」；Anthropic 分析 BrowseComp 表现时发现 token 用量解释 80% 方差。设计启发：浏览器/检索能力要单独评测，且 token 成本是 agent 系统的首要成本变量（多 agent 约 15× chat）。
- **评测维度→设计倒推**：任务完成度→用终态校验；工具正确使用/规则遵守→错误工具调用与规则违反是最常见失败，需在 system prompt 给 policy + 确定性规则层兜底；一致性（pass^k）→需要非 LLM 的护栏；成本→控制 token 与工具调用次数；安全→单独注入/外发测试集；用户满意度→τ-bench 式用户模拟器。

## 权限与审批模式

- **Claude Code 五档**：default(Manual，首个工具调用逐个确认) → acceptEdits(自动接受文件编辑+常见文件命令) → plan(只读探索) → auto(后台安全检查自动放行) → dontAsk(只放行预批准工具) / bypassPermissions(全跳过，仅限隔离容器)。规则优先级 deny > ask > allow；「权限规则由 Claude Code 执行，不由模型遵守」是核心设计。
- **Codex 双轴**：approval_policy（on-request 默认 / never / granular 细粒度 / 托管环境 untrusted）+ sandbox_mode（read-only / workspace-write / danger-full-access），网络默认关闭；`approvals_reviewer="auto_review"` 可用审阅 agent 先过一道数据外泄/凭据探测/破坏性动作检查，风险 action fail-closed（超时单独呈现但动作不执行）。受保护路径（.git/.codex）始终只读。
- **ZCode 本地**：`~/.zcode/cli/db/db.sqlite` 的 `local_setting` 表（scope=project/user, namespace=permission, key=mode, value={"mode":"yolo"}）——每项目一条 permission mode，job-helper 项目当前为 yolo（全自动）。同表结构可借鉴「按项目/会话切档」的模型。
- **两段式确认实现要点**（job-helper 已落地，对照规范）：① 第一段只读/生成摘要不落库；② 第二段带 confirmed:true 才执行落库；③ 执行前校验前置条件（岗位未匹配→JOB_MATCH_REQUIRED）；④ 状态机严格单向+终态不可回退，落库前确认即反悔机会；⑤ 审批确认本身必须是代码强制，不依赖模型自觉。

## 人工确认点设计原则

- **必须确认**：不可逆（覆盖/删除/终态转换）、对外部世界有影响（投递、发送邮件、调用第三方写接口）、个人数据外发（把简历/联系方式传出本地）、沙箱外与联网操作、带 destructive 标注的工具调用。
- **可自动**：只读（list/analyze 只读段）、工作区内可回滚修改、只影响内部临时状态的中间步骤。Claude Code 对「Yes, don't ask again」分两类：Bash 命令确认永久存 settings，文件修改确认仅持续到会话结束——敏感度越高豁免越短。
- **确认 UX**：确认弹窗最小化展示「动作+影响+风险等级」；Claude Code Ctrl+E 可按需生成命令解释（低/中/高风险）而非每次弹；两段式「先看摘要再确认」优于一次性放行。
- **超时处理**：审批超时一律 fail-closed（不执行），Codex auto-review 超时也会阻断执行；过期确认需重新生成摘要，不能复用旧确认。

## 提示注入与沙箱防护

- **工具返回内容视为数据而非指令**：抓取的网页/岗位描述不拼进 system prompt 作为指令来源；不让模型「跟随页面里的指示」。
- **外发控制靠确定性约束而非模型自觉**：Anthropic web_fetch 设计为「只能访问用户输入的 URL 或 companion web_search 返回的 URL」，以此阻断拼接 URL 外泄；该设计被「跟随已抓取页面内嵌链接的 honeypot」绕过（Simon Willison 2026-07 案例），说明「跟随抓取内容里的链接」这类口子要明确封死。
- **输入校验**：LLM 生成的 URL/邮箱/电话必须过白名单/正则/可验证来源核验（job-helper 已有 channel-guard 先例），严禁自创事实类数据。
- **沙箱**：默认只写工作区+受保护路径只读；网络默认关闭/域名白名单（deny 优先）；danger-full-access 仅限隔离环境。Codex web_search 默认 cached 模式（用索引结果）减少任意网页内容暴露面。

## 对 job-helper 的建议

- **P0（必须，防不可逆/外发事故）**：① applyJob/对外发邮件等不可逆动作锁定两段式确认，确认与执行由代码强制；② 若引入网页/渠道内容抓取，抓取内容与 system prompt 隔离、只作数据上下文，且封死「跟随页面内链接/拼接 URL」路径（channel-guard 推广到所有 LLM 生成的 URL/邮箱/联系方式）；③ 任何状态变更落库前必经确认，超时/拒绝=不推进（fail-closed）。
- **P1（应该，工程化）**：① 权限分档模型（readonly / manual / acceptEdits / yolo 至少前两档，参考 ZCode local_setting 的按项目存 mode）：默认 manual（两段式），只读工具免审批，写/落库动作需确认，且「对外发送」类别永不"本次不再问"；② 确认 UX 展示摘要+风险等级+影响面，敏感动作豁免按会话过期而非永久存；③ 审计日志记录工具调用与确认来源（不写敏感原文，遵循 AGENTS.md）；④ 建 20-30 个真实求职场景任务的迷你评测集，参照 τ-bench 用终态校验（投递状态机）而非模型自评，并测 pass^k 一致性。
- **P2（可选，长期加固）**：① 危险命令/操作黑名单（rm -rf 等）作为最终 circuit breaker；② 若接外部 API 或网络，域名白名单+请求体审查（数据外发控制）；③ 提示注入演练测试集（恶意岗位描述/钓鱼网页）验证 agent 不跟随；④ 参照 Codex auto-review，对高风险动作先过一层规则审阅再转人工。
