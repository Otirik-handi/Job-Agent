# 02 Agent 记忆系统

## 调研对象（链接 + 一句话）
- **MemGPT / Letta**（论文 arXiv:2310.08560；https://github.com/letta-ai/letta）：把 LLM 当操作系统，用「核心记忆块 + 归档记忆 + 回放记忆」三层管理上下文，Agent 可自编辑记忆。
- **Generative Agents**（Stanford，arXiv:2304.03442）：25 个小镇模拟人，记忆流（memory stream）+ 检索评分 + 反思（reflection），成为后续记忆系统的参考标准。
- **mem0**（https://github.com/mem0ai/mem0）：通用「记忆层」中间件，对话自动抽取 → 存储 → 检索，2024 年最热开源记忆库之一。
- **Zep / Graphiti**（https://github.com/getzep/graphiti）：基于时序知识图谱（bi-temporal KG）的记忆，事实随时间「作废而非删除」，自动抽取与合并。
- **MemoryBank**（arXiv:2305.10250）：引入艾宾浩斯遗忘曲线，按时间与重要性「遗忘 / 强化」记忆，用于长期陪伴聊天机器人。
- **Voyager**（https://github.com/MineDojo/Voyager）：把「技能」以可执行代码存为长期记忆库，按 embedding 相似检索、可组合复用（并入技能专题，不深挖）。

## 记忆分层模型
各系统命名略不同，但「四层」是共识：

| 层 | 放什么 | 读写时机 | 存储介质 |
|---|---|---|---|
| 工作记忆 | 当前对话轮、最近 N 条消息、当前任务状态 | 每轮读写 | 上下文窗口内 |
| 核心记忆 | 用户画像、偏好、规则、固定状态 | 常驻上下文，Agent 用工具改 | 提示词内 + 持久化（DB/文件） |
| 情景/事件记忆 | 一次性事件、投递记录、对话片段 | 对话后自动抽取写入 | 表/向量，按需检索取回 |
| 长期语义记忆 | 提取的事实、总结、反思 | 事后批处理 | 知识图谱 / SQLite 表 / 向量 |

- **Letta 三层最实用**：core memory blocks（persona / human / 自定义块，每块 label + description + value + limit，常驻上下文、无需检索，底层渲染为 `<memory_blocks>` XML 标签）+ archival memory（外部知识库，embedding 检索）+ recall memory（对话历史语义搜索）。
- **Generative Agents** 用单一「记忆流」存全部经历文本，靠检索把相关者捞回上下文；反思产生高层抽象后再存回流中。
- **Graphiti** 强调事实的时序性：事实带有效窗口（validity window），信息变更时旧事实「作废但不删除」，并保留到原始 episode 的完整溯源。
- **关键取舍**：层越多，检索与去重成本越高；Letta 用「常驻核心块 + 惰性检索」规避每次全量检索——把高频状态放常驻块、低频细节放可检索存储，job-helper 可照此思路。

## 写入策略
- **自动抽取（主流）**：mem0 在会话后做一次 LLM 调用抽取事实（新版为单次 ADD-only，无 UPDATE/DELETE，只累积不覆盖）；Zep/Graphiti 增量抽取并跨会话合并实体。
- **显式声明（基础但必要）**：Letta 让 Agent 通过 memory_replace / memory_append 等内置工具自编辑核心块——用户一句「我本科在 XX 大学」即由 Agent 显式写入，读多写少、写前核对。块描述（description）是 Agent 决定如何读写的关键信号。
- **事后反思**：Generative Agents 在「最近事件重要性分总和」超阈值（实现为 150）时触发，取最近 100 条记录，先生成 3 个高层问题作为检索 query，再生成 5 条 insight，作为反思记忆存回流（可形成反思树）。MemoryBank 按遗忘曲线周期性合并 / 强化记忆。
- **一致性代价**：自动抽取要避免覆盖（mem0 索性 ADD-only 只累积）；显式写入需「写前核对 + 字符限额」防止核心块被写坏。写入逻辑越简单越稳。

## 检索策略
- **Generative Agents 公式（事实标准）**：`score = α_recency·recency + α_importance·importance + α_relevance·relevance`（α 均=1，先 min-max 归一化到 [0,1]）。recency = 指数衰减（衰减因子 0.995 / 游戏小时，距上次访问越久分越低）；importance = LLM 打分 1-10；relevance = embedding 余弦相似度。
- **mem0**：语义向量 + BM25 关键词 + 实体匹配并行打分后融合，叠加时间感知检索。
- **Graphiti**：embedding 相似 + BM25 + 图遍历混合检索，可按图距离重排；时序保证查询到「此刻」正确的事实。
- **Letta**：归档记忆用 embedding 相似检索；回放记忆是对话历史的语义搜索。
- 小结：单用户低数据量不必上多路融合，先「向量相似 + 时间衰减 + LLM 重要性」，必要时叠加关键词即可。

## 上下文压缩与摘要
- **Letta compaction（最成熟）**：默认 sliding_window 模式保留最近 ~70%，把更老的 ~30% 用 LLM 压成滚动摘要块（clip_chars 上限，如 50k 字符）；空间仍不够则 ~10% 递增压缩比例直到放得下。另有 all（全量摘要）、self_compact 系列（带原 system prompt 与工具定义，提升缓存命中）。
- **Generative Agents**：反思本身就是压缩——把琐碎事件沉淀为高层洞察，减少上下文占用。
- **MemoryBank**：遗忘曲线 ≈ 按时间的有损压缩（该忘的忘、重要的强化）。
- 通用模式：原始消息永远落库可溯源，上下文里只留「滚动摘要 + 最近窗口 + 检索到的高相关块」。

## 对 job-helper 的可落地建议（SQLite 单用户）
- **P0 固定核心块（Letta 风格）**：SQLite 表 `memory_blocks(label, description, value, limit)`，预置 resume（学历/技能/年限）、preferences（目标岗位/城市/薪资/远程偏好）、status_scratchpad（当前流程进度），每轮常驻系统提示，Agent 通过工具读写；写入方式 = 用户显式声明 + 会话结束一次 LLM 抽「diff」更新。
- **P0 对话历史**：`messages` 表全量存储，用 SQLite 内置 FTS5 全文检索即可回忆「之前聊过哪家公司」，零依赖。
- **P0 应用事件表**：`applications` 表 + `status_history`（valid_from / superseded_by，模拟 Graphiti 时序作废，不删旧状态）。
- **P1 语义检索**：SQLite 存 embedding BLOB（sqlite-vec 或自算余弦），混合检索 = FTS5 关键词 + embedding 相似 + 时间衰减 × LLM 重要性（1-5 分），无需引入专用向量库。
- **P1 会话级摘要**：`conversations.summary` 字段，长会话结束时压缩旧轮（Letta sliding_window 简化版）。
- **P2 反思 / 复盘**：每 N 次会话或投递里程碑后，LLM 生成「经验教训」（哪类 JD 匹配、面试卡在哪），写入 `lessons` 表并作为常驻块。
- **P2 知识图谱**：单用户量级不需要 Neo4j；需要关系时用规范化表（company / application / job 外键）即可。Letta 新版的 MemFS / git 版本化记忆可作为可选项。
