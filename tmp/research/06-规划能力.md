# 06 Agent 规划能力

> 调研目标：为 job-helper 的求职任务规划（"完成一次求职周报""制定投递计划"等长链条但有明确步骤的任务）提炼可借鉴的规划设计。调研对象覆盖经典推理框架论文与"深度研究（Deep Research）"类产品/开源实现。

## 经典推理框架（一句话概括 + 适用场景）

- **ReAct**：推理轨迹与外部行动交错，每步观察反馈驱动下一步——规划是"渐进式、循环细化"的，不是一次生成完整计划；适用需检索/工具交互的任务（QA、网页操作）。**关键词：随时纠偏、可解释**。
- **Plan-and-Solve**：执行前先显式产出子任务清单再求解，减少零样本 CoT 的漏步/错步；适用步骤明确、顺序强的任务（数学、多步指令）。**关键词：一次规划、顺序执行**。
- **Tree of Thoughts**：不沿单一路径线性前进，在多个候选思维间搜索（含前瞻/回溯），靠自我评估选路；适用首步决策关键、易陷局部最优的任务（Game of 24：ToT 74% vs CoT 4%）。**关键词：分支探索、回溯**。
- **Reflexion**：失败不调权重，而是语言自省存入情景记忆（episodic memory），后续尝试读取教训（HumanEval 达 91% pass@1）；适用试错型、可多次重试的任务。**关键词：失败复盘复用**。
- **CoT**：仅用少量含中间步骤的示例提示，即可大幅提升算术/常识/符号推理（基线方法，一次性铺垫）。

**对规划的启示**：两条路线互为补充——宏观任务适合"先计划再执行"（Plan-and-Solve），微观执行环节天然是 ReAct 式的"观察→调整"循环；失败时叠 Reflexion 式自省。

## 深度研究类产品的规划-执行-迭代流程

**OpenAI Deep Research**（o3 优化版）：用户给一个 prompt → 自主搜索、解读、分析数百来源，"pivoting as needed in reaction to information it encounters"（遇到信息实时转向）；耗时 5-30 分钟；侧边栏实时显示"已执行步骤 + 来源"；最终输出带引用标注的完整报告。**规划特点**：不展示前置计划，是"目标驱动 + 自主迭代转向"，靠侧边栏做过程透明。

**Gemini Deep Research**：启动时先**生成多步研究计划，供用户修改或批准**；批准后迭代执行——"搜索→发现有趣信息→基于所学开启新一轮搜索"，重复多轮；最后综合成带原始链接的报告，可导出 Google Doc。**规划特点**：计划先行 + 用户审批 + 执行中计划随新信息滚动更新（plan-approve-then-execute-replan）。

**STORM**：把长文写作拆为"预写作"三阶段——①发现主题的多视角；②模拟不同视角的作家向专家提问（基于可信来源）；③整理信息成大纲；最后按大纲逐节检索增强生成。**规划特点**：大纲即持久化计划，检索与写作都围绕它。

**GPT Researcher**：planner Agent 生成一组研究子问题 → 多个 crawler 执行 Agent 并行按问题收集 → 每条来源摘要并追踪 → 过滤聚合出最终报告；Deep Research 模式用树状递归、可配深度/广度、子主题并发。

**Open Deep Research（langchain-ai）**：LangGraph 编排，planner 先生成报告章节结构，子研究者并行调研各节，再合成报告；legacy 版本即 Plan-and-Execute（计划+逐节执行+反思）与 Supervisor-Researcher 多 Agent 两种。

**OpenDeepResearcher（mshumer 简化版）**：每轮生成至多 4 个独立查询 → 并行搜索去重 → 并行抓取并判定相关性 → 上下文回灌 LLM，由其决定是否开启下一轮（直到迭代上限，默认 10 轮）→ 最终汇总成报告。

**共性流程**：`粗计划（章节/问题集/大纲）→ 并行调研 → 汇总/自评 → 决定是否补搜 → 迭代至满足或达上限 → 成文`。计划粒度是"节/问题"级而非"步骤"级，给执行留空间；轮次上限是硬终止条件。

## 任务分解与计划持久化/恢复

**层级分解**：深研类普遍两层——上层按报告结构拆（章节/大纲/问题集，STORM、GPT Researcher），下层按搜索动作拆（OpenDeepResearch 每轮 4 个并行查询）。编码类按职责链拆（Devin 示例：建分支→研究代码→改代码→提 PR→处理反馈）。

**并行性**：深研子任务天然相互独立，用并行 Agent/并行搜索提速（GPT Researcher crawler、OpenDeepResearch 并行查询）；编码类任务依赖顺序强（改代码前先研究代码），并行收益低，靠循环推进。

**依赖**：求职/深研类链条是"弱依赖"，用清单顺序即可；编码类是"强依赖"，需显式步骤顺序（Devin 的步骤编号、Task Specification）。

**计划持久化**：
- **文件/清单即计划**：Devin 在 prompt 中内嵌编号步骤 + checklist（PR 描述里的检查项、Task Specification 明确"成功标准/禁止动作"）；计划落到会话/文件，可传给下一个 session。
- **事件日志即状态**：OpenHands 把"状态"定义为 event stream——所有历史 action + observation 的全量时间线，中断后从事件流重放即可恢复；这是最可靠的恢复原语。
- **会话持久化**：Devin 云端会话跨设备可继续（Ask 会话生成计划、可"Send to Devin"转 Agent 执行）；LangGraph 用 checkpointer 快照图状态。
- **面向用户可见**：OpenAI 侧边栏实时步骤+来源、Gemini 计划先审后执行、Devin 计划/checklist 展示——规划同时是进度透明机制。

**崩溃/中断恢复的三种模式**：①事件日志重放（OpenHands）；②计划文件 + 勾选状态（checklist 标记 done/in_progress，重启后读文件续跑）；③会话对象持久化（Devin/LangGraph checkpointer）。

## 规划失败模式

1. **过度规划**：把细粒度步骤一次性穷举，执行时环境已变导致计划全废。对策：Devin 官方建议"3 小时内任务直接做，大任务拆成多个聚焦 session"；深研产品只规划到节/问题粒度。
2. **规划与执行脱节**：计划生成后不随观察更新，照旧执行过时步骤。对策：ReAct 式每步反馈更新、Gemini 的"基于所学再搜"、OpenAI 的"pivot"。
3. **计划僵化/发散**：要么拒绝偏离原计划错过新线索，要么无限迭代没有止境。对策：OpenDeepResearch 设迭代上限；Reflexion 在失败后必须重估下一步而非硬推。
4. **幻觉与错误引用**：深研类产品官方承认的局限——可能错误推断、引用不可靠，需用户核实。对策：来源追踪（citation）+ 用户可验证。
5. **上下文/成本失控**：长任务积累大量中间结果（深研 5-30 分钟、数百来源），需汇总压缩再喂回，否则超出上下文。

## 对 job-helper 的建议

**现状**：单 Agent + 单一 SYSTEM_PROMPT + SQLite 消息表，无规划层。求职任务是"链条较长但有明确步骤"（周报：收集投递记录→分析数据→起草→审阅；投递计划：定目标→选岗位→排序→执行→复盘）。

**P0（先做）**
1. **分层混合规划**：宏观计划一次性生成并持久化（plan-then-execute），微观步骤在执行时按需生成（ReAct 式循环）。具体：任务开始时由主 agent 产出 3-6 个任务级步骤 + 每步成功标准，写入计划文件；每步执行时再细化具体动作，不预先穷举。
2. **计划文件 + 状态清单持久化**：`plans/<task_id>.md`（或 JSON），记录步骤列表、每步状态（todo/in_progress/done/blocked）、依赖顺序、产出物路径、失败备注。会话中断后读计划文件续跑（对应 OpenHands event stream + Devin checklist 模式）；SQLite 已有消息表，新增 plan 表即可。
3. **面向步骤的观察→重规划循环**：每步执行后更新计划状态，并由 agent 判定"下一步照计划 / 调整计划 / 提前终止"；终止条件 = 所有步骤 done 或达到用户确认的边界（如周报完成即交付）。

**P1（后做）**
4. **不引入独立 planner Agent**：单用户场景用 prompt 承担 Planner 角色足够；仅当计划复杂且需用户确认时参考 Gemini 的"计划先行→用户批准→执行"（求职周报可由用户先点头再跑）。
5. **依赖建模用简单字段即可**：`depends_on` 列表（周报的"分析"依赖"收集"），无需 DAG 引擎；可并行子任务（多岗位调研）通过既有工具并行执行。
6. **Reflexion 式失败复盘**：blocked 步骤记录失败原因，计划文件保留教训，后续任务/周报可复用（对齐记忆层设计）。

**P2（可选）**
7. **计划进度对用户可见**：参考深研侧边栏，把当前步骤/已完成项注入对话展示。
8. **来源/产出追踪**：每步产出物落盘并记录路径，支持用户核对（对齐深研 citation 思路）。
9. **任务级总结沉淀**：任务结束后把"计划+结果+教训"汇总归档，成为长期记忆的一部分。
