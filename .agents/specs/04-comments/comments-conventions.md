# 代码注释规范（comments-conventions.md）

> 代码注释的组织与写法约定（现状沉淀：横切前端 / 后端 / Agent 三层已稳定一致的实践）。
> 为什么：注释实践跨三层重复一致，需要权威清单防止注释风格漂移与冗余膨胀。

## 语言

- 注释一律中文（含 `eslint-disable` 后的原因说明）；`code` 符号、路径、专有名词保留英文
- 为什么：对齐 AGENTS.md 中文沟通约定，团队唯一语言

## 克制原则

- 代码自解释优先：命名即文档，注释只解释**"为什么"与"契约边界"**，不解释"是什么"
- 禁止逐行翻译式注释（`// 循环遍历数组` 这类）
- 为什么：冗余注释随代码演进而失真，比没有注释更有害

## JSDoc 覆盖（选择性）

- 导出函数/类型/契约在**行为不明显或边界重要**时用 `/** */` 写明用途、行为、前置/后置条件（参考 `apply-state.ts`、`resume-text.ts`、`resume-edits.ts`、`schemas/*.ts`）
- 自解释导出（如 `use-*.ts` hooks、仓储 CRUD 函数）**不强制** JSDoc
- 为什么：契约层是 LLM 产物与校验的边界，值得文档化；其余命名足够时注释是噪音

## 复杂逻辑必写"为什么"

- 坑、类型桥接、非显然决策必须用块注释解释来龙去脉（参考 `tool-factory.ts` 泛型桥接说明）
- 为什么：防止后续维护者误解或"清理"掉必要的桥接/防御代码

## eslint-disable 必附原因

- `// eslint-disable-next-line <规则> -- <中文原因>`，原因具体到问题与依据
- 为什么：lint 豁免是例外，无原因的豁免无法审计

## JSX 区块标记

- 结构复杂的 JSX 用 `{/* 区块说明 */}` 标记主要区块（头像指示器、气泡、操作区等）
- 为什么：长 JSX 的可读性，区块边界一眼可辨

## 引用来源

- 涉及设计决策/经验教训的注释引用文档编号：`第 N 期设计第 X 节`、`经验 #N`
- 为什么：注释与权威文档可追溯，避免注释成为无出处的二把手规范

## 敏感信息禁入

- 密码、token、Provider key、完整简历文本、完整 JD、LLM 请求体**一律不进注释**
- 为什么：对齐 AGENTS.md 硬约束；注释进入 git 历史，删除代码不等于删除历史

## 禁止遗留 TODO

- 不留 TODO/FIXME/XXX 标记；临时标记须在当批提交内清理
- 为什么：现状零遗留，TODO 是未完成工作的噪音，跨批遗留即失效
