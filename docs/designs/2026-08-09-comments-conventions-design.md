# 代码注释规范设计

日期：2026-08-09
状态：草稿 → 待审阅
关联规范：AGENTS.md（中文沟通、敏感信息硬约束）、`.agents/specs/00-governance/spec-autonomy.md`（新增条件、内容边界）
设计依据：代码注释现状（`src/`、`app/` 各层已稳定一致的注释模式）

## 1. 背景与需求

`.agents/specs/` 已有 4 份规范（00 治理 ×2、01 前端、02 后端、03 Agent），缺少跨层通用的**代码注释约定**。

对照 spec-autonomy「新增规范的条件」：注释实践在代码中跨层重复一致（见第 2 节），满足立规范条件。注释规范是**横切主题**（前端/后端/Agent 三层均适用），不归属任何单一代码域。

**定位：现状沉淀**——固化代码中已稳定一致的注释实践，横切三层。不改现有代码，后续新代码一律遵循。

## 2. 现状核实（规范内容来源）

- **语言**：注释几乎全中文（对齐 AGENTS.md），`code`/路径符号保留英文
- **JSDoc `/** */`**：用于导出函数/类型/契约的用途+行为+边界（`apply-state.ts`、`resume-text.ts`、`resume-edits.ts`、`schemas/*.ts`、`tool-factory.ts` 类型、`message-bubble.tsx` 组件）
- **选择性覆盖**：自解释导出（`use-*.ts` hooks、仓储 CRUD 函数）无 JSDoc——不强制
- **大段"为什么"注释**：复杂逻辑/坑/桥接（`tool-factory.ts` 泛型桥接 8 行说明）
- **eslint-disable 附中文原因**：`-- <原因>`（tool-factory 两处、agent 层 2 处）
- **JSX 区块标记**：`{/* 头像指示器 */}`、`{/* 气泡 */}`（message-bubble）
- **引用来源**：注释引用设计/经验编号（`第 4 期设计第 2 节`、`经验 #6`）
- **零遗留**：无 TODO/FIXME/XXX

## 4. 规范内容大纲

1. **语言**：注释一律中文（含 `eslint-disable` 后的原因说明）；`code`/路径等符号名保留英文
   - 为什么：对齐 AGENTS.md 中文沟通约定，团队唯一语言
2. **克制原则**：代码自解释优先，注释解释"为什么"与"契约边界"，不解释"是什么"；禁止逐行翻译式注释
   - 为什么：命名即文档，冗余注释增加维护成本
3. **JSDoc 覆盖**：导出函数/类型/契约在行为不明显或边界重要时用 `/** */` 写明用途、行为、前置/后置条件；自解释导出不强制
   - 为什么：现有选择性注释模式，契约层是 LLM 产物与校验的边界
4. **复杂逻辑必写"为什么"**：坑、类型桥接、非显然决策用大段块注释解释
   - 为什么：防后续维护者误解或"清理"掉必要的桥接代码
5. **eslint-disable 必附原因**：`// eslint-disable-next-line <规则> -- <中文原因>`
   - 为什么：豁免是例外，无原因的豁免无法审计
6. **JSX 区块标记**：结构复杂的 JSX 用 `{/* 区块说明 */}` 标记主要区块
   - 为什么：长 JSX 的可读性
7. **引用来源**：涉及设计决策/经验教训的注释引用文档编号（`第 N 期设计`、`经验 #N`）
   - 为什么：注释与权威文档可追溯
8. **敏感信息禁入**：密码/token/key/完整简历/JD/LLM 请求体不进注释
   - 为什么：对齐 AGENTS.md 硬约束；注释进入 git 历史，删除不等于删除历史
9. **禁止遗留 TODO**：不留 TODO/FIXME/XXX；临时标记须当批提交内清理
   - 为什么：现状零遗留，TODO 是未完成工作的噪音

## 5. 验收标准

1. `.agents/specs/04-comments/comments-conventions.md` 就位
2. 规范遵守 spec-autonomy：条目可执行，每条附一行"为什么"
3. 规范内容与现有注释实践一致（抽查对照 tool-factory、message-bubble）
4. 设计 + 计划 + 规范文件按流程落盘并 commit

## 6. 边界（不在本期）

- ❌ 不重写、重构现有注释
- ❌ 不引入注释检查工具（如 eslint 注释规则）——规范先落地，工具化留待需要时
- ❌ 不覆盖文档注释（README/设计/计划文档另有规范体系）
