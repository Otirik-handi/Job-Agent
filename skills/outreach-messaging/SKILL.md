# 主动触达（打招呼/私信/邮件）

## 1. 核心原则

- 主动触达不是求职信——求职信是"应申请之邀证明匹配"，触达是"主动引起注意"。
- 目标是听起来像**真正注意到公司某个具体点的聪明人**，不是广播履历的候选人；不推销、不套话。
- 所有内容基于真实经历与可查证的公司事实，**不虚构项目、不夸大数据**。

## 2. 写前调研四件套（缺料先要）

1. **公司角度**——官网/JD/About 页找一件值得提的具体事（近期产品/业务数字/技术决策）
2. **收件人名字**——团队页/招聘页/"Hi [名字]"永远优于"Hi 招聘负责人"；查不到就降级称呼并提示可补充，不阻塞
3. **相关项目**——把用户最相关的工作匹配到岗位领域
4. **栈重叠**——只在真实匹配时提

- 有 JD 无公司信息：先 webSearch/webFetch 调研（company-research skill），仍缺则先向用户要。

## 3. 六段结构（三形态共用）

- **开场钩子（Hook，2-3 句，必须公司特定）**：
  - 好：公司材料里的具体数字（"市场只有 5% 在线"）；显示你懂领域的产品决策；来自 JD 的技术洞察
  - 坏：泛泛（"我爱你们做的东西"）、含糊（"你们的使命让我共鸣"）、吹捧（"你们是这行最激动人心的公司之一"）
- **简介（Body，3-5 句）**：当前角色 → 相关过去 → 一两个最相关项目；上下文式而非列表；**无成就列表**（"我提升了 X%"）——让项目自己说话
- **连接（Connection，1-2 句）**：与具体角色的桥——"你们要找的是〔角色真正要的〕——这正是我在做的工作，说实话我觉得自己很匹配"；感觉像观察，不是声称
- **Gap 披露（必要时，1 句）**：岗位要求年限多于候选人有余时**简短承认并重定向**："岗位提到 5 年——我有 3 年，但我交付的是生产级，我更希望你能直接判断"（直面差距不道歉）
- **关键条件披露（必要时，1 句）**：如远程/异地意愿等影响匹配的条件提前说明
- **收尾（Closing，低压自信）**："我目前在〔公司〕，对下一步持开放态度。我觉得我的经验很适合你们在做的事——所以我想我们双方都能从一次对话中获益。"**避免**："期待您的回复""请见附件简历""我很希望能有机会……"

## 4. 国内三形态与长度分档

| 形态 | 长度 | 要点 |
|---|---|---|
| BOSS 直聘打招呼 | ≤300 字 | 极简版：hook 一句 + 简介一句 + 一句请求（"方便的话想请教/聊聊这个岗位"） |
| 脉脉/领英私信 | 100-200 字 | hook + 连接 + 低压收尾；留一个明确下一步 |
| 邮件 | 200-300 词 | 六段完整结构；主题行简单直白（如"快速介绍 — 姓名"），无点击诱饵 |

- 通用规则：**"能适用于任何公司的句子都删"**；每句都要挣得它的位置。

## 5. 常见错误自检（生成后逐项过）

1. **太自信**："我会是你们团队杰出的补充" → "我觉得我会是强匹配"——陈述信念，不声称确定
2. **太谦卑**："我知道我可能没有你们要的全部经验……" → 直面差距并继续，不道歉
3. **太长**：三段列举每个成就 → 一段背景、一段连接
4. **太泛**：以"我写信是为了表达对……的兴趣"开场 → 以具体吸引点开场
5. **无调研**："我爱你们的产品和使命" → 用具体数字/决策/洞察（hook 标准见 §3）

## 6. 边界与联动

- **触发区分**：写求职信（cover-letter-generation，被动应投递）vs 主动触达（本 skill）——用户说"写求职信"走前者，"主动联系/打招呼/私信/跟进"走后者
- **跟进场景**：投递后无回应（约 7 天）→ 简短跟进（hook 不变 + 一句"想确认是否收到，若有进展期待同步"），不重复完整模板
- **缺料先澄清**：缺目标公司/岗位/简历时先问（意图澄清协议），不凭空生成
- 触达内容生成即交付，无需落库；若需记录"触达了谁/何时"，与投递审计扩展联动（投递-版本关联同批评估）
