# JD 解析规则

## 1. 适用场景与边界

- 适用：拿到 JD 全文后，需要把散落的要求整理成结构化清单，供后续匹配、求职信、面试准备复用
- 边界：解析只做提取与归类，**不评判求职者是否满足**（那是 job-matching 的职责）；对 JD 中含糊表述（如"熟悉常用框架"）保留原样并标注含糊，不替 HR 补全含义
- 产出：职责清单 + 硬性/软性要求 + 关键词 + 红线 + 证据出处

## 2. 解析步骤

### 2.1 通读并切分

- 先通读全文，按"职责 / 要求 / 福利 / 公司介绍 / 流程说明"切块；福利与公司介绍不进要求清单，单独摘出参考

### 2.2 提取职责（做什么）

- 逐条列出岗位职责，保留原文粒度（不合并意思不同的条目）
- 每条职责标注动词类型：**日常执行**（负责/维护/支持）vs **项目攻坚**（主导/搭建/优化/从 0 到 1），后者是重点加分项

### 2.3 硬性要求（必须满足）

判断依据（满足任一即可判为硬性）：

- 出现"必须""要求""需具备"等强限定词
- 明示年限门槛（如"3 年以上经验"）
- 学历硬性表述（如"本科及以上"且无"可放宽"）
- 明确列出证书/语言等级（如"CET-6""PMP"）
- 招聘流程前置（如"需先通过笔试/机考"）

硬性要求逐条列出，标注原文出处，不得合并或弱化。

### 2.4 软性要求（加分项）

判断依据：

- 出现"优先""加分""了解""熟悉更佳"等弱限定词
- "熟悉/了解"级别但未标年限的能力项
- 福利性描述（如"有内推资源"）

软性要求也要逐条列出（求职信与面试准备会用到），标注"加分项"。

### 2.5 关键词抽取

- 从全文抽取 5-10 个高频或核心词（技术栈、工具、方法论、行业术语），如"React""数据仓库""OKR"
- 用途标注：这些词是简历匹配、求职信埋词、面试准备的重点

### 2.6 红线识别（硬门槛）

红线 = 不满足即被筛掉的要求，独立成节，与硬性要求区分（红线是"门槛"，硬性要求可能还有部分弹性）：

| 类型 | 示例 | 说明 |
|---|---|---|
| 学历 | 硕士以上 / 统招本科 | 无学历弹性表述即为红线 |
| 年限 | 5 年以上 | 明确年限且无"优秀者可放宽" |
| 证书/资质 | 注会/一建/执业医师 | 无证即不满足 |
| 硬技能 | 必须精通某语言/平台 | 与软性"了解"区分 |
| 其他 | 年龄/性别/户籍/出差要求 | 按原文如实列出，不做道德评判 |

## 3. 输出格式

按以下结构输出（每条均带证据出处，含糊处标注【含糊】）：

1. **职位概况**：岗位名称、级别、地点、薪资范围（如有）、工作性质（全职/实习）
2. **职责清单**：日常执行项与项目攻坚项分开列
3. **硬性要求**：编号列出，附原文摘录
4. **软性要求（加分项）**：编号列出
5. **红线**：表格列出，不满足即不建议投递（交由 job-matching 结论，这里只列事实）
6. **关键词**：核心词列表
7. **参考信息**：福利、公司介绍等不进清单的内容

## 4. 注意事项

- 解析结果必须可追溯到原文：任何一条要求都要能指出 JD 里哪里写的
- JD 缺失的部分（如没写薪资）标注"JD 未提及"，不推断
- 同一意思重复出现的要求只保留一次，但保留最严格表述（如"3 年以上"与"5 年以上"并存时取 5 年）
- 解析完成后提示下一步：可继续做匹配分析（job-matching）、写求职信（cover-letter-generation）或准备面试（interview-prep）
